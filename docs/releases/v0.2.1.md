# ShutterDB v0.2.1

Compaction uses a hard link for its rollback backup, avoiding a full copy of the old
log. Filesystems without hard-link support still use a copy.

Benchmarks now cover bounded-cache eviction, write latency, reads and reopening,
alongside SQLite/RocksDB storage comparisons. Raw results and commands are in the
performance report.

The C++ API and format v1 are unchanged; no database migration is needed.
After interrupted compaction, reopen and close with v0.2.1 before using an older version.
