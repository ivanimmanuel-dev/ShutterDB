# ShutterDB v0.2.1

Compaction retains the original log through a hard link on supported filesystems,
avoiding a full backup copy. Filesystems without link support use the existing copy
procedure. Recovery and read-only inspection handle interrupted replacements.

A new bounded-cache benchmark measures automatic eviction, write pauses, reads and
reopening. The performance report includes these results and fresh SQLite/RocksDB
measurements, with raw results and reproduction commands.

The C++ API and format v1 are unchanged; existing databases need no migration.
After interrupted compaction, reopen and close with v0.2.1 before using an older version.
