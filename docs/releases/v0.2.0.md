# ShutterDB v0.2.0

This release adds persistent caches with a disk budget and improves log scanning,
checksumming and indexed reads.

## Changes

- `shutter::Cache` provides LRU eviction, automatic compaction and cache statistics.
  Its default budget is 1 GiB; writes are buffered until `sync()`.
- Opening and verification scan through a reusable read window. Replay updates
  existing index entries in place.
- CRC32C uses runtime-detected x86-64 instructions with a portable fallback.
  Indexed reads fetch and validate a record in one buffer.
- The preview-cache example accepts PNG/JPEG sources and writes PNG previews with
  transparency. Content hashes enable reuse across filenames and process restarts.
- The comparison harness covers SQLite and RocksDB, repeated updates, compaction
  and reopening on 64 MiB and 1 GiB datasets. [Results and method](../asset-cache-v02-results.md).

## Upgrade

Format v1 is unchanged; existing databases need no migration. The `DB` API retains its
synchronous-write default and explicit deletion policy. `Cache` uses the same file
format but can evict entries, including when opening a file over its configured budget.

Install matching headers and library files. Both APIs link through `ShutterDB::ShutterDB`.
The library and CLI retain their dependency-free build. The optional image example
requires OpenSSL, libpng 1.6+ and libjpeg.
